# 에이전트 초기 작업 프롬프트

아래 프롬프트는 코드 에이전트에게 전달하여, 패키지 작성 전에 프로젝트 초기 세팅을 맡길 때 사용한다.

---

## 1. 에이전트에게 전달할 프롬프트

```text
당신은 공공 SI, 전자정부프레임워크, Spring Boot, React, PostgreSQL 기반 프로젝트 경험이 풍부한 시니어 IT 개발자입니다.

작업 목표:
아직 코드 구현을 시작하지 않은 빈 Repository에서 프로젝트 초기 구조를 정리해주세요.
이번 작업에서는 Java 패키지나 React 앱을 생성하지 말고, 문서와 기본 폴더 구조만 정리합니다.

배경:
이 프로젝트는 "보건소 스마트 예약·대기 및 혼잡도 분석 시스템"입니다.
보건소의 예방접종, 건강검진/검사, 건강상담 업무를 대상으로 예약, 현장 접수, 대기번호 발급, 직원 호출, 처리 완료, 혼잡도 분석을 제공하는 공공보건 운영 지원 시스템입니다.

현재 상태:
- GitHub Repository는 생성되어 있거나 생성 예정입니다.
- backend, frontend, docs 폴더는 아직 없습니다.
- 설계 문서 ZIP 파일은 준비되어 있지만 아직 docs 폴더에 배치되지 않았습니다.
- 패키지 작성과 코드 구현은 다음 단계에서 진행합니다.

이번 작업 범위:
1. Repository 루트에 다음 폴더를 생성해주세요.
   - backend
   - frontend
   - docs

2. docs 폴더 안에 다음 하위 폴더를 생성해주세요.
   - 01_planning
   - 02_domain
   - 03_database
   - 04_api
   - 05_frontend
   - 06_dashboard
   - 07_test
   - 08_deploy
   - 09_agent

3. 준비된 설계 문서를 아래 기준으로 배치해주세요.
   - 01_프로젝트_기획서.md → docs/01_planning/01_프로젝트_기획서.md
   - 02_요구사항_정의서.md → docs/01_planning/02_요구사항_정의서.md
   - 03_사용자_역할_권한_정책서.md → docs/01_planning/03_사용자_역할_권한_정책서.md
   - 13_개발_일정_및_우선순위.md → docs/01_planning/04_개발_일정_및_우선순위.md
   - 05_Bounded_Context_명세서.md → docs/02_domain/01_Bounded_Context_명세서.md
   - 04_업무_흐름도.md → docs/02_domain/02_업무_흐름도.md
   - 07_공통코드_정의서.md → docs/02_domain/03_공통코드_정의서.md
   - 15_공통코드_관리_설계서.md → docs/02_domain/04_공통코드_관리_설계서.md
   - 06_ERD_및_테이블_명세서.md → docs/03_database/01_ERD_및_테이블_명세서.md
   - 08_API_명세서.md → docs/04_api/01_API_명세서.md
   - 09_화면_설계서_v0_프롬프트.md → docs/05_frontend/01_화면_설계서_v0_프롬프트.md
   - 10_대시보드_지표_정의서.md → docs/06_dashboard/01_대시보드_지표_정의서.md
   - 11_테스트_시나리오.md → docs/07_test/01_테스트_시나리오.md
   - 12_배포_설계서.md → docs/08_deploy/01_배포_설계서.md
   - 14_코드_에이전트_작업_가이드.md → docs/09_agent/01_코드_에이전트_작업_가이드.md
   - 16_에이전트_프롬프트_및_코드작성_지침.md → docs/09_agent/02_에이전트_프롬프트_및_코드작성_지침.md

4. docs/00_README.md를 작성해주세요.
   내용에는 문서 읽는 순서, 코드 작성 전 반드시 확인할 문서, MVP 기준을 포함해주세요.

5. 루트 README.md를 작성해주세요.
   내용에는 프로젝트 소개, 핵심 목표, 기술 스택, Repository 구조, 문서 위치, 현재 상태, 다음 단계를 포함해주세요.

6. backend/README.md를 작성해주세요.
   아직 백엔드 프로젝트 생성 전이라는 점과 예정 기술, 예정 패키지 구조를 적어주세요.

7. frontend/README.md를 작성해주세요.
   아직 프론트엔드 프로젝트 생성 전이라는 점과 예정 기술, 주요 화면을 적어주세요.

8. .editorconfig를 작성해주세요.
   조건:
   - charset = utf-8
   - end_of_line = lf
   - indent_style = space
   - indent_size = 4
   - insert_final_newline = true
   - trim_trailing_whitespace = true
   - max_line_length = 120

9. .gitignore를 작성해주세요.
   포함:
   - OS 파일
   - IDE 파일
   - Java/Gradle 빌드 파일
   - Node 파일
   - 로그 파일
   - 환경변수 파일
   - 임시 파일

10. docker-compose.yml 초안을 작성해주세요.
    이번 단계에서는 PostgreSQL 컨테이너만 포함해주세요.
    backend와 frontend 서비스는 프로젝트 생성 후 추가합니다.

제한사항:
- 이번 작업에서는 Java 패키지, Spring Boot 프로젝트, React 프로젝트를 생성하지 마세요.
- 코드 구현을 시작하지 마세요.
- 문서와 폴더 구조만 정리하세요.
- 한글 문서가 깨지지 않도록 UTF-8 인코딩을 사용하세요.
- 기존 문서 내용은 임의로 요약하거나 삭제하지 마세요.
- 파일명은 제시된 이름을 유지하세요.
- 실제 커밋은 하지 마세요.
- 작업 후 커밋 메시지 초안만 제안해주세요.

완료 후 보고 형식:
1. 생성한 폴더 목록
2. 생성 또는 이동한 파일 목록
3. 아직 하지 않은 작업
4. 다음 단계 추천
5. 커밋 메시지 초안

커밋 메시지 초안 형식:

- 기획서와 설계 문서 배치
- 루트 README 작성
- backend/frontend 기본 README 추가
- .editorconfig와 .gitignore 추가
```

## 2. 이번 작업 완료 후 다음 프롬프트

초기 세팅이 끝난 다음에는 아래 프롬프트로 백엔드 기본 구조 생성을 요청한다.

```text
당신은 공공 SI, 전자정부프레임워크, Spring Boot, MyBatis 경험이 풍부한 시니어 백엔드 개발자입니다.

작업 목표:
backend 폴더에 Spring Boot 백엔드 프로젝트를 생성하고, 공통 응답/예외 처리와 HealthCheck API까지 구현해주세요.

배경:
프로젝트 문서는 docs 폴더에 정리되어 있습니다.
코드 작성 전 반드시 다음 문서를 확인하세요.
- docs/09_agent/01_코드_에이전트_작업_가이드.md
- docs/09_agent/02_에이전트_프롬프트_및_코드작성_지침.md
- docs/09_agent/03_Codex_GitNexus_UTF8_작업_주의사항.md
- docs/02_domain/01_Bounded_Context_명세서.md
- docs/04_api/01_API_명세서.md

구현 범위:
1. backend 프로젝트 생성
2. Java 17 기준 설정
3. Spring Boot 기반 REST API 프로젝트 구성
4. PostgreSQL, MyBatis 기반 DB 접근 구조 확인
5. Spring Security는 의존성만 추가하고 상세 구현은 다음 단계로 미룸
6. Swagger/OpenAPI 의존성 추가
7. common 패키지 생성
8. ApiResponse 생성
9. ErrorCode 생성
10. CustomException 생성
11. GlobalExceptionHandler 생성
12. HealthCheckController 생성

제한사항:
- 아직 member, reservation, queue 같은 도메인 패키지는 생성만 하고 구현하지 마세요.
- Request/Response/Command DTO는 record를 우선 사용하고, Mapper 조회 결과용 VO의 Setter는 MyBatis 매핑 편의로만 제한하세요.
- 응답 형식은 success, data, error 구조를 사용하세요.
- 예외 메시지는 한글로 작성하세요.
- 빌드 가능한 상태를 유지하세요.
- 실제 커밋은 하지 말고 커밋 메시지 초안만 제공하세요.

완료 후:
- 변경 파일 목록
- 구현 내용
- 실행 방법
- 확인 방법
- 커밋 메시지 초안
을 정리해주세요.
```

## 4. 주의사항

- 첫 작업에서 Spring Boot나 React 프로젝트까지 만들려고 하지 않는다.
- 설계 문서가 안정적으로 배치된 뒤에 backend와 frontend를 만든다.
- docs/09_agent 문서는 코드 에이전트가 항상 먼저 읽도록 한다.
- 문서 파일명은 나중에 찾기 쉽게 번호와 주제를 유지한다.
- 한글 파일명 사용이 불편하면 영어 폴더명 + 한글 파일명 조합을 유지한다.
