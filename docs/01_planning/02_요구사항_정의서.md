# 요구사항 정의서

## 1. 문서 목적

본 문서는 보건소 스마트 예약·대기 및 혼잡도 분석 시스템의 기능 요구사항과 비기능 요구사항을 정의합니다.

## 2. 시스템 범위

### 2.1 MVP 포함 범위

| 구분 | 포함 기능 |
|---|---|
| 인증 | 로그인, 토큰 재발급, 로그아웃, 권한 검증 |
| 사용자 | 예약 신청, 예약 조회, 예약 취소, 혼잡도 조회 |
| 직원 | 현장 접수, 예약자 체크인, 대기열 조회, 호출, 처리 완료 |
| 관리자 | 업무 유형 관리, 창구 관리, 직원 관리, 예약 슬롯 관리, 대시보드 조회 |
| 대시보드 | 시간대별 방문자 수, 업무별 평균 대기시간, 현재 대기 인원, 예약/현장 비율, 노쇼율 |

### 2.2 MVP 제외 범위

| 구분 | 제외 기능 |
|---|---|
| 의료정보 | 검사 결과, 진료 기록, 처방 정보 |
| 알림 | 문자, 카카오 알림톡, 푸시 알림 |
| 비회원 | 예약번호 기반 조회, 비회원 예약 신청 |
| AI | pgvector 기반 검색, 혼잡 원인 요약 |
| 배치 | 일별/시간대별 통계 배치 집계 |
| 하드웨어 | 실제 키오스크, 번호표 출력기 연동 |

### 2.3 2차 확장 범위

| 구분 | 기능 |
|---|---|
| 비회원 | 예약번호 + 휴대폰 번호 기반 예약 조회 |
| 알림 | 예약 완료, 예약 전날, 호출 임박 알림 |
| 추천 | 추천 방문 시간 안내 |
| 키오스크 | 현장 접수 전용 화면 |
| 통계 | 배치 기반 통계 집계 |
| 운영 | 노쇼 자동 처리 |

## 3. 기능 요구사항

### 3.1 인증 요구사항

| ID | 요구사항 | 설명 | 우선순위 |
|---|---|---|---|
| AUTH-001 | 로그인 | 이메일과 비밀번호로 로그인할 수 있어야 합니다. | 상 |
| AUTH-002 | 토큰 발급 | 로그인 성공 시 Access Token과 Refresh Token을 발급해야 합니다. | 상 |
| AUTH-003 | 토큰 재발급 | Access Token 만료 시 Refresh Token으로 재발급할 수 있어야 합니다. | 상 |
| AUTH-004 | 로그아웃 | 로그아웃 시 Refresh Token을 무효화할 수 있어야 합니다. | 중 |
| AUTH-005 | 권한 검증 | 사용자 권한에 따라 API 접근을 제한해야 합니다. | 상 |

### 3.2 예약 요구사항

| ID | 요구사항 | 설명 | 우선순위 |
|---|---|---|---|
| RSV-001 | 업무 유형 조회 | 사용자는 예약 가능한 업무 유형을 조회할 수 있어야 합니다. | 상 |
| RSV-002 | 예약 가능 시간 조회 | 업무 유형과 날짜를 기준으로 예약 가능 시간을 조회할 수 있어야 합니다. | 상 |
| RSV-003 | 예약 신청 | 사용자는 업무 유형, 날짜, 시간대를 선택해 예약할 수 있어야 합니다. | 상 |
| RSV-004 | 예약 중복 방지 | 동일 사용자의 동일 시간대 중복 예약을 제한해야 합니다. | 상 |
| RSV-005 | 예약 인원 제한 | 예약 슬롯의 정원을 초과하여 예약할 수 없어야 합니다. | 상 |
| RSV-006 | 예약 조회 | 사용자는 본인의 예약 목록과 상세 정보를 조회할 수 있어야 합니다. | 상 |
| RSV-007 | 예약 취소 | 방문 1시간 전까지 예약을 취소할 수 있어야 합니다. | 상 |
| RSV-008 | 예약 상태 관리 | 예약 완료, 취소, 체크인, 미방문, 완료 상태를 관리해야 합니다. | 상 |

### 3.3 현장 접수 및 체크인 요구사항

| ID | 요구사항 | 설명 | 우선순위 |
|---|---|---|---|
| VISIT-001 | 예약자 체크인 | 직원은 방문한 예약자를 체크인 처리할 수 있어야 합니다. | 상 |
| VISIT-002 | 현장 접수 | 직원은 예약 없이 방문한 사람을 현장 접수할 수 있어야 합니다. | 상 |
| VISIT-003 | 직원 대리 접수 | 전화 또는 현장 요청을 직원이 대신 등록할 수 있어야 합니다. | 상 |
| VISIT-004 | 방문 이력 저장 | 체크인 또는 현장 접수 시 방문 이력이 저장되어야 합니다. | 상 |
| VISIT-005 | 지각 처리 | 예약 시간 10분 초과 방문자는 일반 대기열로 이동시킬 수 있어야 합니다. | 중 |

### 3.4 대기 관리 요구사항

| ID | 요구사항 | 설명 | 우선순위 |
|---|---|---|---|
| QUE-001 | 대기번호 발급 | 체크인 또는 현장 접수 후 대기번호를 발급해야 합니다. | 상 |
| QUE-002 | 대기열 조회 | 직원은 업무 유형별 대기열을 조회할 수 있어야 합니다. | 상 |
| QUE-003 | 다음 대기자 호출 | 직원은 다음 대기자를 호출할 수 있어야 합니다. | 상 |
| QUE-004 | 처리 시작 | 호출된 대기자를 처리중 상태로 변경할 수 있어야 합니다. | 상 |
| QUE-005 | 처리 완료 | 업무 완료 시 대기 상태를 완료로 변경할 수 있어야 합니다. | 상 |
| QUE-006 | 미응답 보류 | 호출 후 3분 미응답 시 보류 상태로 처리할 수 있어야 합니다. | 중 |
| QUE-007 | 재호출 | 보류 상태의 대기자를 직원이 재호출할 수 있어야 합니다. | 중 |

### 3.5 관리자 요구사항

| ID | 요구사항 | 설명 | 우선순위 |
|---|---|---|---|
| ADM-001 | 업무 유형 관리 | 예방접종, 건강검진/검사, 건강상담 업무 유형을 관리할 수 있어야 합니다. | 상 |
| ADM-002 | 창구 관리 | 업무별 창구를 등록, 수정, 비활성화할 수 있어야 합니다. | 중 |
| ADM-003 | 직원 관리 | 직원 계정과 담당 업무를 관리할 수 있어야 합니다. | 중 |
| ADM-004 | 예약 슬롯 관리 | 업무별 예약 가능 시간과 정원을 관리할 수 있어야 합니다. | 상 |
| ADM-005 | 공지사항 관리 | 사용자 안내 공지사항을 관리할 수 있어야 합니다. | 중 |
| ADM-006 | 공통코드 관리 | 예약 상태, 대기 상태 등 공통코드를 관리할 수 있어야 합니다. | 중 |

### 3.6 대시보드 요구사항

| ID | 요구사항 | 설명 | 우선순위 |
|---|---|---|---|
| DASH-001 | 요약 지표 조회 | 오늘 방문자 수, 현재 대기 인원, 평균 대기시간, 노쇼율을 조회할 수 있어야 합니다. | 상 |
| DASH-002 | 시간대별 방문자 수 | 특정 기간의 시간대별 방문자 수를 조회할 수 있어야 합니다. | 상 |
| DASH-003 | 업무별 평균 대기시간 | 업무 유형별 평균 대기시간을 조회할 수 있어야 합니다. | 상 |
| DASH-004 | 예약/현장 비율 | 예약자와 현장 방문자 비율을 조회할 수 있어야 합니다. | 중 |
| DASH-005 | 노쇼율 | 예약 후 방문하지 않은 비율을 조회할 수 있어야 합니다. | 중 |
| DASH-006 | 현재 혼잡도 조회 | 일반 사용자는 업무별 현재 혼잡도를 조회할 수 있어야 합니다. | 중 |

## 4. 비기능 요구사항

| ID | 구분 | 요구사항 |
|---|---|---|
| NFR-001 | 보안 | JWT 기반 인증과 Role 기반 권한 검증을 적용합니다. |
| NFR-002 | 개인정보 | 의료정보와 검사 결과는 저장하지 않습니다. |
| NFR-003 | 성능 | 예약 가능 시간 조회와 현재 혼잡도 조회는 빠르게 응답해야 합니다. |
| NFR-004 | 확장성 | 단일 보건소 MVP에서 다중 보건소로 확장 가능한 구조를 사용합니다. |
| NFR-005 | 유지보수성 | Bounded Context 기준으로 패키지를 분리합니다. |
| NFR-006 | 문서화 | Swagger/OpenAPI 문서를 제공합니다. |
| NFR-007 | 배포 | Docker Compose로 로컬 실행 환경을 구성합니다. |
| NFR-008 | 접근성 | 사용자 화면은 큰 버튼, 명확한 문구, 단순한 흐름을 지향합니다. |
| NFR-009 | 안정성 | 예약 정원 초과와 중복 예약을 방지해야 합니다. |
| NFR-010 | 감사 추적 | 주요 상태 변경 이력을 추적할 수 있도록 생성일, 수정일, 처리자를 저장합니다. |
