# 사용자 역할 및 권한 정책서

## 1. 사용자 역할

| 역할 코드 | 역할명 | 설명 |
|---|---|---|
| CITIZEN | 일반 시민 | 본인 명의로 보건소 방문 예약을 신청하는 사용자 |
| GUARDIAN | 보호자 | 가족 또는 고령층을 대신해 예약하는 사용자 |
| STAFF | 보건소 직원 | 현장 접수, 체크인, 대기 호출, 처리 완료를 수행하는 사용자 |
| ADMIN | 보건소 관리자 | 업무 유형, 창구, 직원, 예약 슬롯, 대시보드를 관리하는 사용자 |

## 2. MVP 로그인 정책

MVP에서는 모든 사용자를 로그인 기반으로 처리합니다.

| 사용자 | 로그인 필요 여부 | 설명 |
|---|---|---|
| 일반 시민 | 필요 | 예약 신청, 조회, 취소를 위해 로그인 필요 |
| 보호자 | 필요 | 보호 대상자 예약을 위해 로그인 필요 |
| 직원 | 필요 | 현장 접수와 대기 호출을 위해 로그인 필요 |
| 관리자 | 필요 | 관리자 기능 접근을 위해 로그인 필요 |

2차 기능에서는 비회원 예약번호 조회를 추가합니다.

| 2차 기능 | 설명 |
|---|---|
| 예약번호 조회 | 예약번호와 휴대폰 번호로 비회원도 예약 상태를 조회 |
| 비회원 예약 | 로그인 없이 예약 신청하는 흐름은 향후 검토 |

## 3. 인증 방식

| 항목 | 정책 |
|---|---|
| 인증 방식 | Spring Security + JWT |
| Access Token | API 인증에 사용 |
| Refresh Token | Access Token 재발급에 사용 |
| 토큰 재발급 | Refresh Token 검증 후 Access Token 재발급 |
| 로그아웃 | Refresh Token 무효화 |
| 권한 검증 | Role 기반 API 접근 제어 |

## 6. 보안 고려사항

| 항목 | 고려사항 |
|---|---|
| 비밀번호 | 단방향 해시 저장 |
| Refresh Token | DB 또는 Redis 저장 후 무효화 가능하게 관리 |
| 개인정보 | 이름, 휴대폰 번호 등 최소 정보만 저장 |
| 민감정보 | 검사 결과, 질병명, 처방 정보 저장 금지 |
| API 접근 | 인증 필터와 Role 기반 접근 제어 적용 |
| 로그 | 토큰, 비밀번호, 개인정보가 로그에 남지 않도록 처리 |
