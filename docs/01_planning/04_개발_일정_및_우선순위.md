# 개발 일정 및 우선순위

## 1. 개발 원칙

1. MVP 기능을 먼저 완성합니다.
2. 알림, 비회원 조회, 키오스크, AI 기능은 후순위로 둡니다.
3. 백엔드는 eGovFrame Simple Backend Template을 기반으로 배치하고 Maven 구조를 유지합니다.
4. 대시보드는 MVP에서 핵심 지표만 구현합니다.
5. Docker Compose로 실행 가능한 상태를 빠르게 만듭니다.

## 2. 전체 단계

| 단계 | 목표 | 산출물 |
|---|---|---|
| 1단계 | 프로젝트 초기 세팅 | eGovFrame backend 템플릿, Frontend 기본 구조 |
| 2단계 | 인증/권한 구현 | 로그인, 토큰, Role 검증 |
| 3단계 | 기준정보 구현 | 보건소, 업무 유형, 창구, 예약 슬롯 |
| 4단계 | 예약 구현 | 예약 가능 시간, 예약 신청, 조회, 취소 |
| 5단계 | 방문/대기 구현 | 체크인, 현장 접수, 대기번호, 호출 |
| 6단계 | 대시보드 구현 | 요약 지표, 시간대별 방문자, 평균 대기시간 |
| 7단계 | 프론트 구현 | 사용자, 직원, 관리자 화면 |
| 8단계 | 배포 구성 | Docker Compose |
| 9단계 | 테스트 및 문서 보완 | 테스트 시나리오, README, 포트폴리오 정리 |

## 3. MVP 우선순위

| 번호 | 작업 | 이유 |
|---:|---|---|
| 1 | 프로젝트 구조 생성 | 모든 개발의 기준 |
| 2 | 인증/권한 | 모든 API 접근 제어의 기반 |
| 3 | 업무 유형/예약 슬롯 | 예약 기능의 기준정보 |
| 4 | 예약 신청/조회/취소 | 사용자 핵심 기능 |
| 5 | 체크인/현장 접수 | 보건소 직원 핵심 기능 |
| 6 | 대기번호/호출/완료 | 시스템 차별화 핵심 |
| 7 | 관리자 대시보드 | 포트폴리오 핵심 기능 |

## 4. 추천 개발 순서

### Backend

1. eGovFrame Simple Backend Template을 `backend` 폴더에 배치
2. Maven 실행 확인
3. Swagger 접속 확인
4. PostgreSQL 18 + pgvector Docker Compose 구성 확인
5. 템플릿 샘플 코드 분석
6. 제거 가능한 샘플 코드 목록 제안 및 정리
7. 공통 응답/예외 구조 정리
8. Security/JWT 구조
9. Member 도메인
10. Office 도메인
11. Reservation 도메인
12. Visit 도메인
13. Queue 도메인
14. Dashboard 도메인
15. Maven 기준 Dockerfile 작성

### Frontend

1. 프로젝트 초기 세팅
2. 로그인 화면
3. 예약 신청 화면
4. 예약 내역 화면
5. 직원 메인 화면
6. 현장 접수 화면
7. 대기열 관리 화면
8. 관리자 대시보드 화면
9. 예약 슬롯 관리 화면
10. API 연동

## 6. 포트폴리오 완성 기준

| 기준 | 설명 |
|---|---|
| 실행 가능성 | Docker Compose로 실행 가능 |
| 시연 가능성 | 예약 → 체크인 → 대기 → 호출 → 완료 흐름 시연 가능 |
| 대시보드 | 최소 3개 이상 차트 또는 지표 표시 |
| 문서화 | 기획서, 요구사항, API, ERD, 흐름도 포함 |
| 코드 구조 | Bounded Context 기준 패키지 분리 |
| 확장 설명 | 비회원, 알림, AI, MSA 확장 방향 설명 가능 |
