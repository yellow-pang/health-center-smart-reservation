# 외부 시연 접속 작업 리스트

## 1. 문서 목적

이 문서는 Jenkins CI/CD와 Docker Compose 배포가 준비된 상태에서, 다른 사람이 브라우저로 접속해 보건소 스마트 예약·대기 시스템을 확인할 수 있게 만드는 다음 작업을 정리한다.

핵심은 아래 두 가지를 분리하는 것이다.

```text
배포 자동화 완료
  -> Jenkins가 main 변경을 감지해 VM Docker에 배포

외부 접속 가능 상태
  -> 외부 브라우저가 frontend와 backend API에 도달 가능
```

Jenkins 배포가 성공해도 서비스가 개인 PC, Windows localhost, Ubuntu VM 내부 IP에만 묶여 있으면 외부 사용자는 접속할 수 없다.
따라서 다음 단계는 네트워크 공개 방식, 도메인/HTTPS, CORS/API URL, 시연 계정, 보안 범위를 정하는 작업이다.

## 2. 현재 확인한 상태

2026-05-17 기준으로 저장소와 문서를 확인했다.

| 구분 | 확인 결과 |
|---|---|
| 브랜치 | `dev` |
| 최근 배포 문서 | `docs/08_deploy/02_Ubuntu_VM_Jenkins_Docker_Compose_배포_계획서.md`, `03_dev_to_main_배포전_확인_체크리스트.md`, `04_Jenkins_VM_배포_운영_가이드.md` |
| Compose | 루트 `docker-compose.yml`에 `postgresql`, `backend`, `frontend` 서비스가 있음 |
| Backend Dockerfile | `backend/Dockerfile` 있음 |
| Frontend Dockerfile | `frontend/Dockerfile` 있음 |
| Jenkins | `Jenkinsfile`, `infra/jenkins/Dockerfile`, `infra/jenkins/docker-compose.jenkins.yml` 있음 |
| 환경변수 예시 | 루트 `.env.example`, `frontend/.env.example` 있음 |
| 외부 공개 문서 | 이 문서에서 신규 작성 |

확인하지 않은 것:

- Jenkins Pipeline이 실제 Ubuntu VM에서 성공했는지
- 외부 네트워크에서 VM으로 접속 가능한지
- 현재 공유기/방화벽/VirtualBox 네트워크 방식
- 실제 도메인 보유 여부
- HTTPS 인증서 적용 여부

## 3. 결론 요약

외부 사람에게 보여주는 방법은 목적에 따라 나눈다.

| 목적 | 추천 방식 | 특징 |
|---|---|---|
| 같은 와이파이 또는 같은 공간에서 확인 | Ubuntu VM Bridged Adapter + VM IP 접속 | 가장 단순하지만 외부 인터넷에서는 접속 불가 |
| 빠른 포트폴리오 시연 URL 공유 | Cloudflare Tunnel 또는 ngrok | 공유기 포트포워딩 없이 공개 URL 가능 |
| 며칠 이상 안정적으로 공개 | 저가 VPS 또는 클라우드 VM 배포 | 가장 운영 환경에 가까움 |
| 집 IP와 개인 장비로 직접 공개 | 공유기 포트포워딩 + Nginx + HTTPS | 가능하지만 보안/망 설정 부담 큼 |

1차 추천:

```text
Cloudflare Tunnel로 frontend와 backend를 각각 공개한다.
```

이유:

- 공유기 포트포워딩 없이 외부 접속 URL을 만들 수 있다.
- Jenkins와 PostgreSQL은 공개하지 않고 frontend/backend만 공개할 수 있다.
- 포트폴리오 설명에서 “로컬 VM은 유지하되 안전하게 터널로 시연 주소를 열었다”고 설명하기 좋다.

도메인이 없고 당장 하루만 보여주면 ngrok도 가능하다. 다만 무료 URL이 바뀔 수 있어서 `NEXT_PUBLIC_API_BASE_URL` 재빌드가 필요할 수 있다.

## 4. 공개 대상 기준

외부에 열어도 되는 것과 열면 안 되는 것을 먼저 고정한다.

| 대상 | 외부 공개 여부 | 이유 |
|---|---|---|
| Frontend `3000` | 공개 가능 | 사용자가 보는 화면 |
| Backend `8080` | 공개 가능, 단 CORS/인증 확인 필요 | 브라우저 API 호출 필요 |
| Swagger | 제한 공개 또는 임시 공개 | 시연에는 유용하지만 API 노출 범위 확인 필요 |
| Jenkins `8081` | 공개 금지 | 관리자 UI와 배포 권한 보유 |
| PostgreSQL `5432` | 공개 금지 | DB 직접 접근 위험 |
| Docker socket | 공개 금지 | 호스트 제어 권한 |

외부 시연에서 최소 공개 URL은 아래 두 개다.

```text
Frontend: https://<app-public-url>
Backend:  https://<api-public-url>
```

프론트엔드는 브라우저에서 API를 호출하므로 `NEXT_PUBLIC_API_BASE_URL`은 반드시 외부 사용자가 접근 가능한 backend URL이어야 한다.

## 5. 권장 1차 방식: Cloudflare Tunnel

### 5.1 준비 조건

- [ ] Cloudflare 계정 준비
- [ ] 도메인을 Cloudflare에 연결하거나, 임시 tunnel URL 사용 가능 여부 확인
- [ ] Ubuntu VM에서 frontend/backend 컨테이너가 정상 실행되는지 확인
- [ ] backend CORS에 frontend 공개 URL을 추가
- [ ] frontend `NEXT_PUBLIC_API_BASE_URL`을 backend 공개 URL로 설정 후 재빌드

### 5.2 목표 구조

```text
외부 사용자 브라우저
  -> https://app.example.com
  -> Cloudflare Tunnel
  -> Ubuntu VM frontend:3000

외부 사용자 브라우저
  -> https://api.example.com
  -> Cloudflare Tunnel
  -> Ubuntu VM backend:8080
  -> Docker network
  -> postgresql:5432
```

공개하지 않는 것:

```text
Jenkins: 8081
PostgreSQL: 5432
Docker socket
```

### 5.3 작업 리스트

- [ ] Cloudflare Tunnel 방식으로 진행할지 결정
- [ ] 공개 도메인 또는 임시 URL 정책 결정
- [ ] frontend 공개 URL 결정: 예 `https://health-demo.example.com`
- [ ] backend 공개 URL 결정: 예 `https://health-api.example.com`
- [ ] `.env`의 `NEXT_PUBLIC_API_BASE_URL`을 backend 공개 URL로 변경
- [ ] `.env`의 `CORS_ALLOWED_ORIGINS`에 frontend 공개 URL 추가
- [ ] Jenkins Credentials `health-center-env-file`에 변경된 `.env` 업로드
- [ ] main merge 또는 Jenkins Build Now로 frontend 재빌드
- [ ] Cloudflare Tunnel에서 `frontend:3000` 라우팅
- [ ] Cloudflare Tunnel에서 `backend:8080` 라우팅
- [ ] 외부 브라우저에서 frontend 접속 확인
- [ ] 로그인 후 주요 화면 진입 확인
- [ ] 브라우저 개발자 도구 Network에서 API가 backend 공개 URL로 호출되는지 확인
- [ ] Swagger 공개 여부 결정

## 6. 대안 1: ngrok 빠른 시연

도메인 설정 없이 빠르게 URL을 공유해야 하면 ngrok을 사용할 수 있다.

### 장점

- 설정이 빠르다.
- 공유기 포트포워딩이 필요 없다.
- 하루짜리 시연에 적합하다.

### 주의

- 무료 URL이 바뀔 수 있다.
- backend URL이 바뀌면 frontend를 다시 빌드해야 한다.
- 공개 URL을 장기간 이력서/포트폴리오에 적기에는 불안정하다.

### 작업 리스트

- [ ] Ubuntu VM에서 frontend `3000`, backend `8080`이 실행 중인지 확인
- [ ] backend용 ngrok URL 생성
- [ ] frontend용 ngrok URL 생성
- [ ] `.env`의 `NEXT_PUBLIC_API_BASE_URL`을 backend ngrok URL로 변경
- [ ] `.env`의 `CORS_ALLOWED_ORIGINS`에 frontend ngrok URL 추가
- [ ] Jenkins Credentials `.env` 갱신
- [ ] Jenkins Pipeline으로 재배포
- [ ] 외부 브라우저에서 frontend ngrok URL 접속 확인

---

## 7. 대안 2: VPS 또는 클라우드 VM

외부 사람이 여러 날 안정적으로 접속해야 한다면 VPS가 가장 단순한 운영 형태다.

### 장점

- 공인 IP가 있다.
- 방화벽, 도메인, HTTPS 구성이 명확하다.
- 포트폴리오에서 실제 서버 배포 경험으로 설명하기 좋다.

### 주의

- 비용이 든다.
- 서버 보안 업데이트와 방화벽 관리가 필요하다.
- Jenkins를 서버에 둘지, GitHub Actions로 바꿀지 결정해야 한다.

### 작업 리스트

- [ ] VPS 제공자 결정
- [ ] Ubuntu 서버 생성
- [ ] Docker, Docker Compose 설치
- [ ] repository clone
- [ ] `.env` 생성
- [ ] `docker compose --env-file .env up -d --build` 수동 성공
- [ ] Nginx 또는 Caddy로 frontend/backend reverse proxy 구성
- [ ] HTTPS 인증서 적용
- [ ] Jenkins를 유지할지 GitHub Actions로 전환할지 결정
- [ ] 외부 브라우저에서 전체 흐름 확인

## 8. 외부 공개 전 보안 체크리스트

외부 시연은 기능 확인이 목적이므로 공개 범위를 작게 유지한다.

- [ ] Jenkins `8081`은 외부 공개하지 않는다.
- [ ] PostgreSQL `5432`는 외부 공개하지 않는다.
- [ ] `.env`와 Jenkins Credentials에 실제 개인 비밀번호를 넣지 않는다.
- [ ] JWT secret은 `.env.example` 값이 아닌 별도 긴 값으로 바꾼다.
- [ ] 데모 계정 비밀번호는 포트폴리오용으로 제한한다.
- [ ] 관리자 계정 공개가 필요하면 데모 데이터만 사용한다.
- [ ] 테스트 후 URL을 닫는 방법을 정한다.
- [ ] Swagger 공개 여부를 결정한다.
- [ ] CORS 허용 Origin을 `*`로 열지 않는다.
- [ ] 브라우저에서 로그인, 예약, 대기열, 대시보드 대표 흐름만 확인한다.

## 9. 외부 접속 검증 시나리오

외부 사람에게 공유하기 전 아래 흐름을 직접 확인한다.

### 9.1 접속 확인

- [ ] 외부 네트워크 또는 휴대폰 LTE/5G에서 frontend URL 접속
- [ ] 로그인 화면 표시
- [ ] 브라우저 개발자 도구 Console 오류 없음
- [ ] API 요청이 backend 공개 URL로 호출됨
- [ ] CORS 오류 없음

### 9.2 대표 계정 확인

기본 seed 계정 기준:

```text
관리자: admin@test.com / password1234
직원: staff@test.com / password1234
시민: user@test.com / password1234
```

- [ ] 관리자 로그인 후 대시보드 확인
- [ ] 직원 로그인 후 대기열 화면 확인
- [ ] 시민 로그인 후 예약 화면 확인

### 9.3 대표 기능 확인

- [ ] 시민 예약 슬롯 조회
- [ ] 시민 예약 신청
- [ ] 직원 현장 접수 또는 예약자 체크인
- [ ] 직원 대기 호출/시작/완료
- [ ] 관리자 대시보드 지표 확인

## 10. 실행 순서 추천

외부 시연을 가장 적은 위험으로 진행하려면 아래 순서로 진행한다.

1. 로컬/VM 내부에서 `docker compose --env-file .env up -d --build` 성공 확인
2. VM 브라우저 또는 Windows 브라우저에서 frontend/backend 확인
3. 외부 공개 방식 선택: Cloudflare Tunnel 우선
4. 공개 frontend/backend URL 결정
5. `.env`의 `NEXT_PUBLIC_API_BASE_URL`, `CORS_ALLOWED_ORIGINS` 수정
6. Jenkins Credentials의 `.env` 갱신
7. Jenkins Pipeline 재실행
8. Tunnel 라우팅 연결
9. 외부 네트워크에서 대표 흐름 확인
10. 시연 후 공개 URL 유지/중지 정책 결정

## 11. 완료 기준

이 작업은 아래 기준을 모두 만족하면 완료로 본다.

- [ ] 외부 사용자가 frontend 공개 URL에 접속할 수 있다.
- [ ] 외부 브라우저에서 backend API 호출이 성공한다.
- [ ] 로그인 후 역할별 주요 화면에 진입할 수 있다.
- [ ] Jenkins와 PostgreSQL은 외부에 공개되지 않는다.
- [ ] 시연 계정과 민감 정보 관리 기준이 문서화되어 있다.
- [ ] 공개 URL, 중지 방법, 문제 발생 시 확인 순서가 기록되어 있다.
