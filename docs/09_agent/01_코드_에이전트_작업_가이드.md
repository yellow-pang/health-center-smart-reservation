## 2.1 백엔드 템플릿 기준

백엔드는 전자정부프레임워크 공식 GitHub의 Simple Backend Template을 기반으로 한다.

원칙:

1. Spring Initializr로 일반 Spring Boot 프로젝트를 새로 생성하지 않는다.
2. eGovFrame Simple Backend Template의 Maven 구조를 유지한다.
3. Maven과 Gradle을 혼용하지 않는다.
4. 전자정부프레임워크 관련 핵심 설정은 임의로 제거하지 않는다.
5. 템플릿 샘플 코드는 먼저 목록을 확인하고, 제거 대상 목록을 제안한 뒤 정리한다.
6. 템플릿 실행 확인이 필요한 경우 사용자가 직접 확인할 수 있도록 실행 기준과 기대 결과를 안내한다.
7. MVP에서는 JPA를 사용하지 않고 MyBatis를 기본 DB 접근 방식으로 사용한다.
8. 신규 보건소 도메인은 `egovframework.healthcenter` 하위 패키지에 작성한다.
9. Mapper XML은 `src/main/resources/egovframework/mapper/healthcenter` 하위에 둔다.
10. 프론트엔드는 React 기반으로 별도 구성하며, 백엔드와 프론트엔드는 REST API로 분리한다.
11. MVP에서는 pgvector 기반 AI 기능을 구현하지 않고, PostgreSQL 18 + pgvector 이미지만 확장 가능성을 위해 사용한다.

## 5. 작업 전 GitNexus 준비

에이전트는 코드 구조 탐색, 영향도 분석, 리팩토링, 디버깅 작업을 시작하기 전에 GitNexus 인덱스 상태를 먼저 확인한다.

도구 실행, PowerShell UTF-8 인코딩, `rg`, `npm.cmd` 사용 주의사항은 `09_agent/03_Codex_GitNexus_UTF8_작업_주의사항.md`를 함께 따른다.

권장 절차:

1. Windows Command Prompt(cmd.exe)를 열고 프로젝트 루트로 이동한다.
2. 프로젝트 루트에서 `gitnexus status`를 실행한다.
3. 인덱스가 없거나 오래된 경우 `gitnexus analyze`를 실행한다.
4. 대규모 구조 변경, 패키지 이동, 주요 기능 구현 후에는 필요 시 `gitnexus analyze`를 다시 실행한다.
5. 임베딩 기반 의미 검색이 명시적으로 필요한 경우에만 `gitnexus analyze --embeddings`를 사용한다.
6. GitNexus 실행이 실패하면 실패 이유를 보고하고, `rg`, 파일 직접 확인, Maven compile/test-compile 등 일반 코드 탐색 절차로 작업을 계속한다.

## 5.1 런타임 검증 운영 기준

에이전트는 권한, 방화벽, 포트 점유, Docker Desktop 권한 문제가 생길 수 있는 런타임 작업을 직접 실행하지 않는다.

| 구분 | 에이전트 역할 |
|---|---|
| Maven compile/test-compile | 직접 실행 가능 |
| 서버 기동 | 사용자가 VS Code Spring Boot Dashboard 등으로 실행할 기준 안내 |
| Docker/Docker Compose | 사용자가 실행할 명령 안내 |
| API 런타임 호출 | Swagger `Try it out` 대표 예시 1개와 기대 응답 안내 |
| Swagger/브라우저 확인 | URL, 인증 방법, 확인할 Controller/Mapping 안내 |
| 포트 점유 프로세스 종료 | 확인/종료 방법 안내 |

완료 보고에서는 빌드/테스트 컴파일과 런타임 확인을 분리한다.

API 런타임 확인 안내는 Swagger를 우선한다. 터미널 PowerShell/curl 예시는 필요한 경우에만 보조로 작성하고, 구현 기록에는 대표 예시 1개만 둔다. 추가 정상/경계/실패 케이스는 PR 문서 체크리스트로 정리한다.

주의:

- GitNexus 인덱스 생성은 코드 이해를 돕기 위한 준비 단계이며, 사용자의 명시 요청 없이 실제 커밋을 수행하지 않는다.
- 아직 코드가 거의 없는 초기 세팅 단계에서는 인덱싱 결과가 제한적일 수 있다.
- 문서만 수정하는 작업에서는 필요 시에만 GitNexus를 사용한다.

## 6. Backend 패키지 구조

```text
egovframework.healthcenter
 ├─ member
 │   ├─ api
 │   ├─ application
 │   ├─ mapper
 │   ├─ policy
 │   └─ dto
 ├─ office
 ├─ reservation
 ├─ visit
 ├─ queue
 ├─ dashboard
 ├─ notification
 └─ common
     ├─ code
     ├─ exception
     ├─ response
     ├─ security
     └─ audit
```

Mapper XML 위치:

```text
src/main/resources/egovframework/mapper/healthcenter
```

DTO/VO 기준:

1. Request/Response/Command DTO는 `record`를 우선 사용한다.
2. Mapper 조회 결과용 VO는 MyBatis 매핑 편의를 위해 Setter를 제한적으로 허용한다.
3. VO의 Setter를 비즈니스 상태 변경에 사용하지 않는다.
4. 예약 취소, 대기 호출, 처리 완료 같은 상태 변경은 Service와 Policy 클래스로 명확하게 분리한다.
5. 조회 서비스는 `@Transactional(readOnly = true)`, 변경 서비스는 `@Transactional`을 사용한다.

## 9. 예약 도메인 핵심 규칙

1. 예약 단위는 30분입니다.
2. 예약 가능 기간은 오늘부터 14일입니다.
3. 당일 예약은 허용합니다.
4. 예약 취소는 방문 1시간 전까지 가능합니다.
5. 업무별 기본 예약 가능 인원은 5명입니다.
6. 관리자는 예약 슬롯의 정원을 변경할 수 있습니다.
7. 예약 슬롯의 정원을 초과하면 예약할 수 없습니다.
8. 동일 사용자의 동일 시간대 중복 예약은 제한합니다.

## 10. 대기 도메인 핵심 규칙

1. 체크인 또는 현장 접수 후 대기번호를 발급합니다.
2. 대기번호는 업무 유형별로 발급합니다.
3. 예약 시간대 안에서는 예약자를 우선 호출합니다.
4. 예약자가 10분 초과 지각하면 일반 대기열로 이동할 수 있습니다.
5. 호출 후 3분 미응답 시 HOLD 상태로 변경합니다.
6. HOLD 상태는 직원이 재호출할 수 있습니다.
7. 처리 완료 시 QueueTicket 상태를 COMPLETED로 변경합니다.
