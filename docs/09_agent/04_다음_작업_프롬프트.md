# 다음 작업 프롬프트

## 문서 목적

이 문서는 다음 코드 작업을 시작할 때 코드 에이전트에게 그대로 전달할 수 있는 프롬프트를 제공한다.

현재 프로젝트는 eGovFrame Simple Backend Template 기반 백엔드에 PostgreSQL 설정과 공통코드 조회 API가 추가된 상태이다. 다음 작업은 신규 기능을 크게 구현하기 전에, PostgreSQL 공통코드 API를 검증하고 샘플 코드 정리 범위를 확정하는 것이다.

## 다음 작업 결론

바로 다음 작업은 아래 이름으로 진행한다.

```text
PostgreSQL 공통코드 API 실행 검증 및 샘플 코드 정리 착수
```

이 작업을 먼저 하는 이유:

- `Globals.DbType=postgresql`로 전환되어 있으므로 PostgreSQL 기준 실행 검증이 필요하다.
- 공통코드 API는 신규 보건소 도메인 구조와 MyBatis mapper 로딩이 실제로 동작하는지 확인하는 최소 기능이다.
- 기존 eGovFrame 샘플 API는 PostgreSQL mapper가 없어 깨질 수 있으므로, 신규 기능 구현 전에 샘플 정리 범위를 확정해야 한다.
- 샘플 코드가 남아 있으면 Swagger, Security, Mapper, 테스트 범위가 혼재되어 이후 Office/Auth/Reservation 구현이 헷갈릴 수 있다.

## 작업 프롬프트

아래 프롬프트를 다음 코드 작업 요청으로 사용한다.

```text
당신은 공공 SI, 전자정부프레임워크, Spring Boot, MyBatis, PostgreSQL, React 기반 시스템 개발 경험이 풍부한 시니어 IT 개발자입니다.

작업 목표:
PostgreSQL 공통코드 API 실행을 검증하고, eGovFrame Simple Backend Template 샘플 코드 정리 범위를 확정해주세요. 안전하다고 판단되는 경우 첫 제거 대상으로 SNS 로그인 샘플부터 정리해주세요.

배경:
이 프로젝트는 보건소 스마트 예약·대기 및 혼잡도 분석 시스템입니다.
백엔드는 eGovFrame Simple Backend Template 기반이며 Maven 구조를 유지합니다.
신규 보건소 도메인은 `egovframework.healthcenter` 하위 패키지에 작성합니다.
Mapper XML은 `src/main/resources/egovframework/mapper/healthcenter` 하위에 둡니다.
MVP에서는 JPA를 사용하지 않고 MyBatis를 기본 DB 접근 방식으로 사용합니다.
현재 PostgreSQL 설정과 공통코드 조회 API가 추가되어 있습니다.

작업 전 읽을 문서:
- docs/README.md
- docs/09_agent/01_코드_에이전트_작업_가이드.md
- docs/09_agent/02_에이전트_프롬프트_및_코드작성_지침.md
- docs/09_agent/03_Codex_GitNexus_UTF8_작업_주의사항.md
- docs/10_backend_transition/02_PostgreSQL_전환_준비_완료_및_다음_작업.md
- docs/10_backend_transition/03_샘플_코드_정리_범위_및_안전_절차.md
- docs/10_backend_transition/04_DB_접근_방식_JPA_MyBatis_판단.md

구현 및 확인 범위:
1. GitNexus 상태를 확인해주세요.
   - 로컬 설치 CLI 기준으로 `gitnexus status`를 사용합니다.
   - 인덱스가 없거나 stale이면 필요한 경우 `gitnexus analyze`를 실행합니다.
   - 현재 설치 버전에는 `detect-change` 계열 명령이 없으므로 변경 범위 확인은 `git status`, `git diff`, `rg`, 빌드로 보완합니다.
   - GitNexus가 실패하거나 stale이면 이유를 기록하고 `rg` 기반 탐색을 병행합니다.
2. PostgreSQL 컨테이너 확인은 직접 실행하지 말고, 사용자가 실행할 명령과 기대 결과를 안내해주세요.
   - 예: `docker compose up -d postgres`
   - 예: `docker compose ps`
3. 백엔드에서 `mvn -q -DskipTests compile`을 실행해 빌드 가능 여부를 확인해주세요.
4. 백엔드 실행은 직접 수행하지 말고, 사용자가 VS Code Spring Boot Dashboard로 실행할 기준과 기대 결과를 안내해주세요.
5. 아래 공통코드 API는 직접 호출하지 말고, 사용자가 Swagger `Try it out`으로 확인할 대표 예시 1개와 기대 결과를 안내해주세요.
   - `GET /api/common-codes/RESERVATION_STATUS`
   - `GET /api/common-codes?groupCodes=RESERVATION_STATUS,QUEUE_STATUS`
6. 추가 확인 케이스는 PR 또는 작업 결과 체크리스트로 정리해주세요.
7. 샘플 코드 정리 후보를 `rg`로 확인해주세요.
   - SNS 로그인 샘플
   - 게시판 샘플
   - 일정 샘플
   - 회원관리 샘플
   - JPA/QueryDSL 테스트 샘플
   - Selenium 테스트 샘플
8. 첫 제거 대상으로 SNS 로그인 샘플이 안전한지 판단해주세요.
9. 안전하다고 판단되면 SNS 로그인 샘플 코드와 설정 참조를 제거해주세요.
10. 안전하지 않으면 실제 삭제 없이 제거 계획과 위험 요소만 정리해주세요.

제한사항:
- Spring Initializr로 새 프로젝트를 만들지 마세요.
- Maven과 Gradle을 혼용하지 마세요.

- JPA Entity와 Repository를 신규 도메인에 만들지 마세요.
- 샘플 코드는 한 번에 전부 삭제하지 말고 기능 묶음 단위로 진행하세요.

- 서버 기동, Docker 실행, API 런타임 호출, Swagger/브라우저 확인, 포트 점유 프로세스 종료는 직접 실행하지 말고 사용자가 확인할 기준과 기대 결과만 안내해주세요.

완료 기준:
```
