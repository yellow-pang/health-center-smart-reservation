# 샘플 코드 정리 범위 및 안전 절차

## 문서 목적

이 문서는 eGovFrame Simple Backend Template에 포함된 샘플 기능을 보건소 스마트 예약·대기 시스템 기준으로 어떻게 정리할지 정의한다.

이미 `docs/10_backend_transition` 문서에 샘플 코드 후보 목록이 있으므로, 이 문서에서는 같은 목록을 반복하지 않고 실제 정리 판단 기준, 제거 순서, 안전 확인 절차만 다룬다.

## 중복 제외 기준

이 문서에서 다시 작성하지 않는 내용:

- 전체 프로젝트 기획과 요구사항: `docs/01_planning`
- Bounded Context 설명: `docs/02_domain/01_Bounded_Context_명세서.md`
- 전체 API 목록: `docs/04_api/01_API_명세서.md`
- 샘플 코드 발견 기록: `docs/10_backend_transition`

이 문서에서 추가로 정리하는 내용:

- 어떤 샘플을 먼저 제거할지
- 어떤 설정은 유지해야 하는지
- 삭제 전 어떤 참조를 확인해야 하는지
- 삭제 후 어떤 기준으로 안전하다고 볼지

## 정리 원칙

1. eGovFrame 핵심 설정은 제거하지 않는다.
2. 신규 보건소 도메인과 무관한 샘플 기능부터 제거한다.
3. 삭제 전 Controller, Service, DAO, Mapper, Test 참조를 확인한다.
4. 한 번에 전체 샘플을 지우지 않고 기능 묶음 단위로 진행한다.
5. 삭제 후 빌드, Swagger, 신규 보건소 API 동작을 확인한다.
6. GitNexus가 stale이면 `rg` 기반 참조 확인을 병행한다.

## 유지해야 할 기반

| 구분 | 유지 이유 |
|---|---|
| `EgovBootApplication` | 애플리케이션 실행 진입점 |
| `egovframework.com.config` | datasource, mapper, transaction, message 등 핵심 설정 |
| `OpenApiConfig` | Swagger/OpenAPI 문서 확인 |
| `SecurityConfig` | 인증/인가 골격 |
| `JwtAuthenticationFilter` | JWT 기반 인증 구조의 출발점 |
| `EgovConfigAppMapper` | MyBatis mapper 로딩 설정 |
| `application.properties` | DB, Swagger, JWT 등 기본 설정 |
| `egovframework.healthcenter` | 신규 보건소 도메인 코드 |
| `egovframework/mapper/healthcenter` | 신규 보건소 mapper XML |

## 제거 우선순위

| 순서 | 대상 | 판단 |
|---:|---|---|
| 1 | SNS 로그인 샘플 | MVP 범위 밖이고 기존 Member/Auth 모델과 분리 예정 |
| 2 | 게시판 샘플 | 보건소 예약·대기 핵심 흐름과 무관 |
| 3 | 게시판 속성/이용정보 샘플 | 게시판 샘플과 함께 정리 |
| 4 | 개인 일정 샘플 | 예약 슬롯 모델과 개념이 달라 혼동 가능 |
| 5 | 회원가입/회원관리 샘플 | 보건소 Member/Role 모델로 재구성 예정 |
| 6 | JPA/QueryDSL 테스트 샘플 | MVP DB 접근 방식은 MyBatis |
| 7 | Selenium 테스트 샘플 | 백엔드 REST API 검증과 우선순위가 낮음 |
| 8 | HSQL 샘플 DB 스크립트 | PostgreSQL 전환 안정화 후 정리 |

## 삭제 전 확인 절차

각 샘플 기능을 제거하기 전에 아래 명령 또는 동등한 탐색으로 참조를 확인한다.

```bash
rg -n "대상클래스명|대상패키지명" backend/src
```

확인할 범위:

| 범위 | 확인 내용 |
|---|---|
| Controller | Swagger에 노출되는 샘플 API인지 확인 |
| Service | 다른 샘플 기능에서 호출하는지 확인 |
| DAO/Mapper | XML namespace와 interface 연결 확인 |
| VO/DTO | 여러 기능에서 공유되는지 확인 |
| Validator | XML validator 참조 확인 |
| Test | 삭제 대상 기능의 테스트인지 확인 |
| SecurityConfig | permitAll 또는 권한 예외 경로 확인 |
| Mapper XML | `let` 하위 mapper 참조 확인 |

## 기능별 삭제 판단

### SNS 로그인

삭제 후보:

- `egovframework.com.sns`
- SNS 관련 application 설정

주의:

- JWT 발급 구조와 섞여 있으면 Auth 구현 전 영향 확인이 필요하다.
- Kakao/Naver 설정값은 MVP에서 사용하지 않는다.

### 게시판

삭제 후보:

- `egovframework.let.cop.bbs`
- `egovframework.let.cop.com`
- 게시판 관련 mapper XML
- 게시판 validator XML
- 게시판 테스트

주의:

- 파일 첨부 기능과 게시판 기능이 연결되어 있을 수 있으므로 파일 공통 기능은 바로 삭제하지 않는다.

### 일정

삭제 후보:

- `egovframework.let.cop.smt.sim`
- 일정 mapper XML
- 일정 validator XML

주의:

- 예약 슬롯과 혼동될 수 있으므로 신규 Reservation Context 구현 전 정리하는 편이 좋다.

### 회원 샘플

삭제 후보:

- `egovframework.let.uss.umt`

주의:

- 기존 로그인 샘플과 회원 관리 샘플의 의존 관계를 확인한다.
- 보건소 Member/Auth 구현 전까지 최소 로그인 검증용 코드가 필요할 수 있다.
- 삭제는 Auth/Member 신규 구현 계획이 확정된 뒤 진행한다.

## 삭제 후 확인 기준

| 기준 | 확인 내용 |
|---|---|
| 빌드 | `mvn -q -DskipTests compile` 성공 |
| 실행 | Spring Boot 실행 성공 |
| Swagger | 불필요한 샘플 API 노출 감소 |
| 공통코드 | `/api/common-codes` 정상 동작 |
| Security | 인증 예외 경로가 의도대로 유지 |
| Mapper | MyBatis mapper 로딩 오류 없음 |

## 완료 기준

샘플 정리는 아래 조건을 만족하면 완료로 본다.

- 보건소 도메인과 무관한 샘플 API가 Swagger에서 제거된다.
- 신규 `egovframework.healthcenter` 구조가 중심이 된다.
- eGovFrame 핵심 설정은 유지된다.
- PostgreSQL 기준 빌드와 실행이 가능하다.
- 이후 Office, Auth, Reservation Context 구현을 시작해도 샘플 코드와 혼동되지 않는다.
