## 개요

관리자가 로그인 중인 상태에서 마감 시간 이후 미처리 대기표가 남아 있으면 화면 상단 알림으로 바로 확인할 수 있게 했습니다.

기존 관리자 대기 마감 화면(`/admin/queue-closing`)과 `GET /api/queues?date=오늘` API를 재사용해 백엔드 변경 없이 프론트 UX만 작게 보강했습니다.

## 변경 내용

- 관리자 전용 마감 알림 컴포넌트 추가
  - 17:30 이후 오늘 미처리 대기표 조회
  - `WAITING`, `CALLED`, `HOLD`, `IN_PROGRESS` 상태만 집계
  - 5분 주기 재조회
  - 최초 감지 시 토스트 알림 표시
  - 같은 날짜 알림 브라우저 단위 숨김 처리
  - 17:30 전에는 `setTimeout`으로 마감 시간까지 대기
  - 백그라운드 탭에서는 주기 조회 중단
- 관리자 레이아웃에 상단 알림 배너 연결
- 구현 기록, PR 문서, 전체 체크리스트, 보류 정리 목록 갱신

## 검증

- [x] `git diff --check`
- [x] `npm.cmd exec -- tsc --noEmit`
- [x] `npm.cmd run build`
- [ ] 브라우저 관리자 로그인 후 17:30 이후 알림 배너 표시 확인
- [ ] 알림의 `마감 관리` 버튼으로 `/admin/queue-closing` 이동 확인
- [ ] 알림 숨김 버튼 클릭 후 같은 브라우저 탭들에서 재표시되지 않는지 확인
- [ ] 백그라운드 탭에서는 주기 조회가 중단되고 다시 보이면 조회되는지 확인
- [ ] Swagger `GET /api/queues?date=YYYY-MM-DD` 확인

## 추가 테스트 체크리스트

- [ ] Happy: 마감 시간 이후 미처리 대기표가 있으면 관리자 화면 상단에 알림이 표시된다.
- [ ] Happy: 알림의 마감 관리 버튼을 누르면 `/admin/queue-closing`으로 이동한다.
- [ ] Edge: 미처리 대기표가 없으면 알림이 표시되지 않는다.
- [ ] Edge: `COMPLETED`, `NO_SHOW`, `CANCELED`만 있으면 알림이 표시되지 않는다.
- [ ] Edge: 숨김 처리 후 같은 날짜, 같은 브라우저에서는 알림이 다시 표시되지 않는다.
- [ ] Edge: 백그라운드 탭에서는 주기 조회가 멈추고, 탭이 다시 보이면 필요한 경우 조회한다.
- [ ] Bad: 대기열 조회 API 실패 시 화면 렌더링은 유지되고 알림만 표시되지 않는다.

## 미검증 사유

- 서버 기동, Docker 실행, Swagger 런타임 호출, 브라우저 확인은 프로젝트 운영 기준상 사용자가 직접 수행한다.
- 마감 기준 시간은 1차 구현에서 프론트 상수 17:30으로 두었고, 보건소별 운영시간 설정은 후속 고도화로 남긴다.
- 마감 대상 count 전용 API 또는 다중 상태 필터 API는 백엔드 계약 추가가 필요해 후속 고도화로 남긴다.

## 후속 작업

- 운영 마감 시간을 백엔드 설정 또는 보건소 운영시간 데이터로 전환
- 알림 읽음/무시 상태를 서버에 저장할지 검토
- 마감 대상 count 전용 API 또는 다중 상태 필터 API 검토
- WebSocket/SSE 기반 실시간 알림 검토
- 2일 경과 미처리 대기표 자동 `NO_SHOW` 배치 검토
