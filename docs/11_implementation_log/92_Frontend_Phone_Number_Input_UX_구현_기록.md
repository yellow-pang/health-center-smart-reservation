# Frontend Phone Number Input UX 구현 기록

## 1. 작업 목표

- 전화번호 입력 시 사용자가 하이픈(`-`)을 직접 입력하지 않아도 되도록 프론트엔드 입력 방식을 개선한다.
- 백엔드로 전송되는 전화번호 값은 기존 API/DB 저장 형태인 `010-1234-5678` 형식을 유지한다.
- 백엔드, DB, API 계약은 변경하지 않고 프론트엔드의 입력 UX만 작은 단위로 수정한다.

## 4. 구현 내용

- `frontend/src/lib/phone-number.ts`
  - 전화번호 입력값에서 숫자만 남긴 뒤 최대 11자리로 제한한다.
  - `01012345678` 입력은 `010-1234-5678`로 정규화한다.
  - 사용자가 하이픈을 붙여 붙여넣어도 동일한 형태로 정리한다.

- `frontend/app/citizen/reservations/new/page.tsx`
  - 예약 신청의 방문자 휴대폰 번호 입력에 자동 정규화를 적용했다.

- `frontend/app/staff/walk-in/page.tsx`
  - 현장 접수의 방문자 휴대폰 번호 입력에 자동 정규화를 적용했다.

- `frontend/app/admin/staff/page.tsx`
  - 관리자 직원 추가/수정 연락처 입력에 자동 정규화를 적용했다.

- `frontend/app/register/page.tsx`
- `frontend/app/find-id/page.tsx`
- `frontend/app/reset-password/page.tsx`
  - 인증 보조 화면의 휴대폰 번호 입력을 제어 입력으로 바꾸고 자동 정규화를 적용했다.

## 5. 데이터 형태 유지 확인

- 예약 생성 요청의 `visitorPhone` 필드명은 변경하지 않았다.
- 현장 접수 요청의 `visitorPhone` 필드명은 변경하지 않았다.
- 관리자 직원 생성/수정 요청의 `phone` 필드명은 변경하지 않았다.
- 화면 상태값 자체를 하이픈 포함 형태로 유지하므로 기존 백엔드 요청과 DB 저장 형태가 유지된다.

대표 요청 예시는 기존과 동일하다.

```json
{
  "serviceTypeId": 1,
  "reservationSlotId": 1,
  "visitorName": "홍길동",
  "visitorPhone": "010-1234-5678"
}
```
